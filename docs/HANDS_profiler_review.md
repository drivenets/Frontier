# HANDS simulator-profiler review

Review date: 2026-10-07. Scope: the available working trees, recorded collection and validation artifacts, and recoverable historical dependency source. No GPU benchmarks or implementation changes were made.

## A. Executive assessment

**HANDS has credible evidence of an operational profiling-to-simulator pipeline for specific MI355X workloads. The available evidence does not establish a generally trustworthy production-latency predictor.** Successful collection, installation, simulation, and handoff generation are documented for Qwen3-0.6B, TP 1/2/4. DeepSeek-V3 work includes real profile updates, simulator runs, and runtime comparisons. These are substantive achievements. They do not, by themselves, establish that the timed kernels match production execution or that predictions generalize across shapes, parallelism, routing, and scheduling regimes.

The most consequential findings are:

- **Timing and execution contracts remain inconsistent with production in important paths.** The historical profiler used for Gate C measures eager event spans or sums traced kernel durations. These are different quantities; neither establishes production graph/fusion fidelity. HANDS's own isolated experiments show substantial, shape-dependent eager/graph differences and unresolved differences between installed profiles and later eager measurements. Its recorded Qwen3 monolithic comparison overpredicts latency by about 1.95×. A universal correction factor is unsupported. [H7, H8, H9; F1–F3, F6]
- **Two conditional semantic defects are demonstrable.** The historical Frontier forced RoPE fallback rotates only the first half-head-width of flattened Q/K and does not distinguish interleaved rotation correctly. HANDS's normal vLLM API adapter does not repair that branch. The current HANDS MLA wrapper uses an upper-left causal mask for chunked prefill with a cached prefix, where a lower-right mask is required. Small CPU checks reproduce both errors. This does **not** show that the recorded default collections took either failing path. [C1, C2 below]
- **Several safeguards are real but narrower than their descriptions.** The block-table fix allocates disjoint request blocks; QK-norm parity is wired into both planner modes; API/source guards reject unexpected implementations; measurement methods and file hashes are recorded. Conversely, the token-coverage gate does not validate operator values, the optional MLA phase filter is not enabled by the standard planner and does not patch the historical shared trainer, and a scalar prediction dictionary is incorrectly described as a lookup of measured grid values. [C3–C5; D]
- **The four reference root causes do not all transfer unchanged.** Eager event scopes remain exposed to Python/GC submission stalls. Kernel-duration summation avoids directly counting those host gaps. The inspected HANDS timing loop does not use spin backlog, so the specific post-spin transient is not applicable there. The reference ROCclr 1000-command barrier was demonstrated on ROCm 7.0; its presence and impact on HANDS's recorded ROCm 7.2.3 cannot be asserted without a trace. [B1–B5; R1]
- **Current external state is not reproducible from these checkouts alone.** HANDS refers to `/work/simulation/Frontier`, which is absent here. Its recorded historical commit is recoverable, but later external profiler changes and the live installed datasets are not available in that location. Historical code findings are explicitly separated below from current HANDS code and from reported runtime outcomes. [F]

**Use recommendation:** retain these data for bounded exploratory comparisons and for testing the simulator under the explicitly profiled execution regime. Do not certify absolute production latency, broad placement rankings, or unprofiled model/hardware configurations from the present evidence. Trust in a particular decision needs the targeted measurement and consumer checks in section E. The existing failures do not justify discarding every row: unaffected semantic paths can be retained, tracer data may be re-extracted, and some integration defects require retraining rather than recollection.

## Execution path actually reviewed

1. **Configuration and tasks.** HANDS does not contain a self-contained replacement profiler. Its collection drivers install compatibility patches and invoke external `frontier.profiling.{linear_op,attention,moe}.main`. Model architecture, token/context grids, TP/EP, block size, dtype and timing method drive the external wrappers. Task 65 records the exact Gate C image digest, model revision and eight invocations. Step 72's committed attention driver installs RoPE, RMSNorm, block-table, FP8 and MLA adapters, then creates a vLLM configuration and calls external attention `main`. Configuration is not globally invariant: the Gate C record specifies O0/custom-ops `all`; the later driver constructs a default `VllmConfig`, so the earlier policy must not be assumed for every later collection. [H1:35–115; F8; `dc-sim/docs/tasks/track-b-step72-deterministic-moe-scratch/run_attention_profile.py`:1–45]
2. **Operator execution.** Historical linear profiling constructs a synthetic block with random weights/inputs, uses explicit model head dimensions and TP-local Q/K/V sizes, runs QKV plus Q/K norm in `attn_pre_proj`, RoPE separately, and output projection with reduction disabled. It substitutes random attention output between linear scopes. Attention profiling separately prepares tensors, persistent paged cache and sequence metadata; `TORCH_SDPA` scatters cache entries and gathers/assembles K/V before calling SDPA. The HANDS MLA adapter adds latent projections and per-request attention. The linear classes are Frontier-owned wrappers, not vLLM classes merely because their names match: their GEMM dispatcher reaches vLLM dispatch or Torch fallback under explicit conditions; the installed provider implementation is not available here. These are isolated synthetic operator workloads, not full vLLM model execution. [F1, F4–F5, F8; H2:128–151; H6]
3. **Timing.** Historical linear event mode: allocate inputs, three warmup forwards, synchronize, clear timing store, twenty active forwards, synchronize, summarize. Record-function mode instead repeats the block inside the traced model. Historical attention event mode uses three warmups/five active forwards; its record-function branch originally invoked `forward` only once. Later Step 72/73 external changes repeat attention twenty times. Event timers allocate/record events around Python scopes; kernel-only extraction correlates scope-contained launch records to GPU kernel events and sums their durations. [F1–F3, F5; H10–H11]
4. **Aggregation and files.** Event `elapsed_time` is milliseconds; trace durations are converted from microseconds to milliseconds. Both paths emit min/max/mean/median/std/count, losing the ordered sample series from the CSV; trace JSON is separately written in `profiler_traces/`. Method-specific files distinguish `linear_op.csv` / `attention.csv` / `moe.csv` from `_kernel_only` siblings. Gate C combined per-TP columns by name, preserving sparse replicated versus sharded rows; its manifest records installed hashes. Historical worker code checks GPU identity, propagates task exceptions, and rejects empty/missing-time-stats linear output. Multi-GPU results are gathered in completion order, which is not a recorded chronological sample order. Sequential mode reuses a wrapper across token points; process workers construct one per task, so setup/cache history differs by execution mode. [F2–F3, F8; H2–H3]
5. **Consumption.** Planner constructs topology, deployment and rank groups; enables fabric-aware collectives and selected guards; creates CLI configuration, asserts dummy mode is off, seeds the process and invokes `Simulator`. Exceptions become explicit result errors. In the recoverable predictor, PD-AF decode pools default to kernel-only, but a DECODE_ATTN batch containing prefill selects events; prefill pools select events; monolithic defaults to events unless graph mode is configured. Models train on filtered profile frames; scalar query dictionaries are populated from model predictions, while MLA has an exact-feature lookup plus model fallback. Historical cache hashes include the training dataframe and predictor configuration/method, helping prevent reuse across changed data. [planner:548–640, 674–711; F6–F7]
6. **Communication and accounting.** Planner's `collective=True` replaces the collective factory with `EngineCCBackend`, even if the CLI names a different backend. The engine prices placement-specific transfers, converts nanoseconds to milliseconds, and uses ring rounds for all-reduce. Isolated linear projections omit TP reductions, so a separate communication term is a valid design. It is incorrect to conclude that communication is absent merely because compute profiling uses one GPU, or to evaluate the current planner against Frontier's default analytical collective class. Actual overlap and critical-rank behavior remain separate validation questions. [H13; F4:473–482; H9:96–108]

## C. Detailed material findings

### Confirmed defects and contract gaps

#### C1. Historical forced RoPE branch still performs the wrong operation

**Evidence:** F4 `common/layers/rotary_embedding.py`:117–185,239–274,554–597; current [RoPE adapter](/home/dn/HANDS/dc-sim/src/integration/profiling/rope_api_adapter.py):109–196 and installation logic. The adapter remaps vLLM API arguments (`rotary_dim`/`base` to the new interface), checks source identity, and rejects unsupported/conflicting signatures. It patches the loader, not the pure-Torch helper.

**Trigger:** `FRONTIER_PROFILING_FORCE_TORCH_FALLBACK` or `FRONTIER_PROFILING_FORCE_TORCH_ROPE_FALLBACK`, and the historical disabled-timer condition, select the local implementation. Its cosine/sine inputs have half-head width; `_apply_rotary_pos_emb` treats that as the complete rotary dimension and slices flattened Q/K without reshaping per head. Its NeoX and interleaved branches are identical.

**Observed versus expected:** a CPU test extracted the two historical helper functions with AST, used random Q/K and head size128, and compared to explicit per-head NeoX rotation. At Qwen3-30B Q32/KV4 and TP1/2/4/8, respectively, **98.4375%, 96.875%, 93.75%, 87.5%** of Q coordinates were exactly unchanged by the fallback. Correct full-head RoPE rotates every head's rotary portion. Maximum absolute output errors in this seeded check were 4.40–5.76. This is a semantic failure, not a timing interpretation.

**Scope/confidence:** high for the historical branch; default Gate C vLLM execution is not proven affected. H2's statement that fallback is reachable only with disabled timing is incomplete because force environment flags also exist. Normal-adapter signature tests and finite positive timings are not numerical equivalence tests. The reference's vLLM0.9.2 native-vs-fused dispatch finding cannot simply be assumed for HANDS's vLLM0.27.1.

**Action/data:** correct the fallback or reject it for collection, add both rotation styles/partial rotary dimensions/multiple heads, and record the actual implementation/provider. Recover environment and trace evidence before deciding existing RoPE rows' status. Recollect rows collected on the wrong branch; no multiplicative transformation can repair timing of the wrong computation.

#### C2. Current MLA cached-prefix prefill has an incorrect causal mask

**Evidence:** [MLA adapter](/home/dn/HANDS/dc-sim/src/integration/profiling/mla_attention_wrapper_adapter.py):233–258 carries `context_len = processed_prompt_len + prompt_chunk_len`;346–370 gathers that full context;373–390 calls SDPA with `is_causal=True` on query length equal only to the current chunk.

**Trigger:** positive processed prefix with non-square Q/K sequence dimensions. For a chunk appended to an existing context, query row `i` must attend through `prefix_len+i`, not only through key `i`.

### Credible measurement risks and unresolved runtime questions

#### R1. Event timing remains exposed to GC, host starvation and runtime batching; kernel-only is a valid but incomplete mitigation

**Evidence:** F1:115–179, F2 timer enter/exit and store:31–38, F3:101–156. Event start/end enclose Python calls and asynchronous submissions; end synchronization guarantees completed work before reading elapsed times, not continuous GPU work between timestamps. No GC isolation is present in the inspected event loop. `PERF_COUNTER` synchronizes around a host interval and therefore intentionally has another inclusive boundary; it is not established as the Gate C dataset's method.

The reference GC intervention linked Python collection pauses to event spans; it did not establish that all medians were unusable. HANDS has the necessary exposure, but no local evidence of the same 150–290ms events. Kernel-only sums kernel durations and therefore avoids directly counting a stalled Python thread as kernel work. This is a sound alternative to adding a backlog. GC/host activity can still alter GPU idleness, clocks and caches, and traced execution can perturb timing; “kernel-only” is not immunity to workload history.

The reference run-position RCA had **two distinct mechanisms**. First, low-activity spin backlog produced an early-to-late timing decline; real GEMM backlog and settle forwards reduced it, with a remaining roughly 0.9–1.3% effect at TP1/2. Shader-clock drift explained only part of the original behavior. HANDS's inspected loop has no such spin, so absence of our backlog fix is not a defect. Second, ROCclr7.0 flushed after 1000 commands since synchronization, including event commands, inserting a system-fence marker. The reference's anomalous run numbers (such as20/118) were consequences of that harness's command sequence, not universal repetition thresholds. HANDS's 20-forward loop contains many scopes and commands per forward; fewer than1000 forwards says nothing decisive. Conversely, its ROCm7.2.3 runtime cannot be declared to share the old barrier without evidence.

**Smallest validation/data decision:** a few small/large shapes with event and kernel trace, GC callbacks, ordered samples, GPU clocks and command accounting. A GC-correlated event-only spike supports direct host contamination; stable kernel sums and stable medians would support retaining those labels within a kernel-only contract. For a barrier, identify actual markers and repetition-dependent placement, then perform a controlled runtime-setting comparison. Re-extract traces if sufficient; aggregate-only CSVs cannot reconstruct removed outliers/order. Do not subtract one fixed host overhead from every shape.

#### R2. Synthetic operator costs do not yet have a validated mapping to serving costs

**Evidence:** F4's preprojection includes QKV plus Q/K normalization and splitting at503–526; reduction-disabled output projection at473–482; random attention substitution at546; input/residual alias at1088–1097. F5's SDPA path includes tensor gathering/stacking, cache scatter, and per-request work for ragged requests. H6's MLA decode loops over requests at405–443 and uses separate projection/einsum calls. These boundaries can be valid if the consumer prices exactly those operations and accounts separately for everything else.

**Recorded evidence of material regime dependence:** H7 reports M32 `mlp_up_proj` installed median0.03922ms versus later eager0.01821ms and graph0.009938ms. H8:133–167 reports attention eager/graph ratios2.369× and1.452× at two decode shapes, and5.697× at a five-token prefill shape. These are real operator experiments in the records, but graphing the same portable wrapper is not proof that it matches the serving engine's kernel provider. Nor do these few points isolate all of Track A's full-system bias.

H15:126 says the installed profile is graph-captured; this conflicts with F1/F5 and the later capture-scope report H7c. That statement should not be used as evidence. Named Python timing scopes do not automatically generate per-operator statistics on graph replay; whole-forward capture requires either device-level attribution or a new composite consumer boundary. Graph capture is a valid option, not a mandatory implementation prescription.

**Additional semantic/cache risk:** `residual = hidden_states` aliases buffers in the historical harness, unlike an independently carried residual. The eventual provider may mutate one or both. Static input/cache reuse and artificial attention-output generation establish a hot synthetic regime but not production cache/memory pressure. Once-per-forward embedding/final norm/head/sampling and engine scheduling/launch overhead must be audited in the consumer ledger: the non-MTP scalar operator list does not itself establish complete coverage of these costs. This review does not equate absence from that list with proof of omission from every other layer.

**Action/data:** compare the dominant one or two physical serving scopes at one matched shape, including dtype, bias, epsilon, local head dimensions, residual aliasing, kernel names and cache layout. For fused serving scopes, use composite measurements or a validated allocation; do not add two isolated measurements for one fused kernel. The reference SGLang fused-RoPE/KV and fused-collective observations are questions to test on vLLM0.27.1, not established HANDS defects. Existing synthetic data can remain useful for that explicitly synthetic execution regime; production reuse needs matched measurements or a validated mapping.

#### R3. Statistical and provenance evidence is uneven across families and revisions

**Evidence:** H1–H3 pin image/model and installed hashes, but the full installed files are external. H7c records a later installed Qwen linear file with290 rows/174 unique coordinates, versus186 originally installed; the old manifest alone cannot certify this later state. H10 reports an external attention-loop correction; H11 reports the complete DeepSeek attention recollection. Neither change should be inferred from historical F5 alone.

**Locally verified raw artifacts:** the three committed Step72 CSVs contain64 TP1 decode attention rows,64 EP4 MoE rows and32 EP8 MoE rows. All eight attention scope count columns equal20, including inactive scopes whose medians are zero. In both MoE files, grouped-GEMM counts equal20, but gating-linear, top-k and shuffling counts equal1. Thus “count20” must be qualified by operator. These single observations are not necessarily wrong means, but cannot establish repeatability or meaningful tails for those scopes.

Warmup and free-device checks are good practice. They do not demonstrate stable clocks or an uncontended host. H8 documents concurrent tenants and variable host load; the different signs of installed-versus-new eager discrepancies prevent attributing everything to one uniform contention factor. The reference's own per-row clock evidence shows why three forwards are not a general settling criterion.

**Action/data:** archive exact consumed CSVs, commands, environment, source commit plus diff, provider identities, trace files and ordered samples; check counts and stability per active scope. #### R4. Schema and configuration filtering are not complete semantic identities

**Evidence:** explicit head dimensions are correctly used during historical tensor construction (F4/F5), but dense attention row/filter identity at F5:388–400 and F6:1223–1229 lacks `head_dim`; the filter uses hidden size, Q/KV heads, block size and effective TP, not provider identity. Distinct implementations can share these dimensions. Method validation and dataframe-based cache hashing are real protections (F6/F7), but cannot distinguish omitted semantics. HANDS EP discovery explicitly omits `expert_hidden_dim` from its matching triple and documents that future mixed files could return too broad an EP set ([planner](/home/dn/HANDS/dc-sim/tools/planner.py):56–96).

**Scope:** this is a conditional selection risk, not evidence that the specific Qwen3-0.6B file mixed two head dimensions. TP>KV replication is handled by the historical worker resolver; rejecting all TP>KV configurations would be an incorrect “fix.” BF16 Gate C evidence does not validate FP8 or another quantization scaling policy. The FP8 adapter's explicit supported/unsupported paths are useful but do not establish numerical or performance equivalence with serving.

**Action/data:** make architecture, head dimension, attention layout/phase, dtype, quantization/scale policy, provider/version, graph/compilation regime and method part of a dataset contract and cache identity. A manifest can supply constants rather than repeating every field per row, provided it is mandatory and checked. Re-key/retrain when provenance is known; recollect when different unidentified regimes have already been merged.

#### R5. Distributed accounting has a sound separation but incomplete runtime validation

**Evidence:** H13 implements fabric-aware ring transfers with replica-aware group selection and a single ns→ms boundary. Planner enables it in both architectures. F4 explicitly disables local TP reductions. This supports separate compute and communication pricing, and avoids declaring an omitted profiler collective an automatic missing simulator cost.

**Open issues:** no reviewed all-rank production timeline proves the correspondence among modeled collectives, actual RCCL algorithms, overlap with compute, expert routing traffic, and the slowest rank. A one-GPU TP-shaped compute measurement samples one shard under synthetic conditions; it does not measure rank imbalance. Kernel sums can also overstate critical-path latency when kernels overlap, even while excluding dispatch gaps. The reference's warning about double-counting an all-reduce inside fused normalization applies only if the selected HANDS serving provider actually fuses it.

**Action/data:** a single TP2 request/step with rank0/rank1 timestamps, one collective, and a simulator component ledger is enough to check units, byte counts, multiplicity, sum versus max, and overlap. If the compute boundary excludes communication and the consumer adds each transfer once at the proper dependency, retain the separation. If a serving kernel includes the collective, change the mapping/ledger and retrain as needed; this need not invalidate unrelated compute rows.

#### R6. Improved profile fitting is not yet validated runtime prediction

**Evidence:** F6/F7 fit and score on the training frame. H12 correctly calls the later cost-weighted MoE residuals (1.4%/2.6%) in-sample, and reports the EP4/n32 worsening to21.2%. H11 reports a separate TP8-held-out attention calibration MAPE4.23%, explicitly standalone and not wired into live prediction. Those are useful diagnostics, with different scopes.

The deterministic MoE rows make local routing agree with the simulator's intended balanced allocation: one local expert assignment per token with other top-k positions assigned outside the local rank. This is a defensible conditioning experiment. It is not evidence that the real model's learned router has that distribution. Similarly, the seed fixes and arrival-regime experiments in H9 show that batching/arrival configuration can reverse simulator rankings. A small confidence interval across simulation seeds does not include systematic profile/scheduler error.

**Action/data:** freeze one latest dataset/model version; first hold out shapes and independent collection runs, then compare a matched serving workload with actual batch/sequence/routing distributions. Report absolute TPOT/TTFT/throughput, ranking uncertainty and component residuals separately. Reuse correct measurements; repair consumer scheduling/accounting where traced discrepancies occur. Do not tune an overall scalar solely to make one comparison pass.

## D. Strengths and valid alternatives

- **API compatibility and task failure handling are fail-closed in useful places.** RoPE argument conflicts, RMSNorm interface variants, block-table and other monkeypatches have signature/source guards. Historical multiprocess workers propagate errors with the failed shape and reject inconsistent GPU mapping; empty linear output is rejected. [F8] The local RoPE guard rejected this review environment's different reference implementation; that is evidence of a functioning guard, not evidence that the recorded supported environment is broken. [H5; F checks]
- **Some semantic bugs have concrete fixes.** Disjoint attention blocks, QK-norm parity at collection and evaluation, dense-model routing guards and replica-aware collective selection address real failure modes. Task69 records successful evaluation after earlier failures rather than relabeling the failures as success. [H4–H5, H13]
- **Kernel-duration summation is a valid alternative to backlog engineering.** It addresses direct host-gap inclusion without sharing the exact spin-backlog condition. It still needs attribution, clock and consumer-boundary validation. [F3; Q/10]
- **Separating communication from local compute is legitimate.** The engine's topology-aware transfer model can be more appropriate than a placement-blind collective table, provided its algorithms and overlap assumptions are validated. [H13]
- **Evidence distinguishes some important scopes.** Image/model pins, column-name merging, file hashes, method-specific files, deterministic-routing annotations, recent in-sample labels and explicit negative hardware comparisons are strong foundations. A smaller short-context Gate C grid is acceptable for its stated workload; it need not replicate our much larger Qwen3-30B/AITER grid. [H1–H4, H9–H12]
- **Alternative production contracts remain possible.** A validated inclusive step-latency model, per-operator kernel costs plus separately measured engine overhead, or composite fused/graph scope costs can all work. The requirement is consistent accounting and demonstrated predictive accuracy, not copying our chosen measurement loop. [Q/10; H7c]
